# Landscape

What others ship that overlaps with pgmandate, going by their own documentation as of November 2026, checked again on the 27th. What is particular to pgmandate, and what it shares with others, is in [scope.md](scope.md#what-it-brings).

| Approach | Examples | What it decides | Relation to pgmandate |
|---|---|---|---|
| Gateways and cloud agent platforms | AgentCore Policy (Cedar, and temporal policies in Dogwood), agentgateway, Docker, Permit.io and TrueFoundry MCP gateways | Allow, deny or ask, per tool call, in front of the tool. Many hold the tool's credential. AgentCore's temporal policies also count and sum calls within one session, over at most 24 hours, and a policy can run in a log-only mode first | Complementary, and overlapping where a gateway holds the key. A mandate is a named person's grant over months, with a policy reference, on your own Postgres, and a person decides what it does not cover |
| Framework approval steps | OpenAI Agents SDK, LangChain/LangGraph, Claude Agent SDK, Temporal and Inngest waits | A pause for a person inside one run | Complementary. pgmandate gives them standing permission, a budget and one record across frameworks |
| Protocol and tool prompts | MCP elicitation; from the 2026-07-28 specification, multi round-trip requests (`input_required`) | The tool server asks the user, through the agent's own client, before it acts | Complementary. No standing permission and no shared record |
| Human review services | gotoHuman | A review request as data, a webhook when it is done | Close in shape, and a hosted service. pgmandate adds standing mandates with a budget, on your own database |
| Identity, vaults and asynchronous approval | Microsoft Entra Agent ID, Okta, Auth0 for AI Agents, Keycard, Infisical Agent Vault | Who the agent is and where the key lives. Auth0's asynchronous authorization also asks a person to approve one specific transaction | Overlapping. Auth0 closes the first gap in [the problem](scope.md#the-problem); pgmandate adds standing mandates, budgets and a record of authority |
| Policy engines | Cedar, OPA, Cerbos, OpenFGA | Yes or no per request | Complementary. No queue for a person and no record of authority |
| Governance libraries | Microsoft Agent Governance Toolkit | Policies in the agent's process, with budgets, approvals in ordered stages (its approval protocol lists a quorum as a [future extension](https://microsoft.github.io/agent-governance-toolkit/adr/0030-action-bound-approval-protocol/)), and a chained audit log | Overlapping. It runs inside the agent; pgmandate runs outside it, on a database the agent cannot reach |
| Approval layers of the same kind | Preloop, SidClaw, Countersign, OpenLeash, withHuman, awaithumans | Policy, approval and a hash-chained audit around an agent's tool calls; Preloop can require a justification per tool and takes decisions from a phone or chat; OpenLeash lets agents propose policies to their owner | Closest in intent. Mostly in front of the tool or in the agent's process; pgmandate's difference is the database as a second gate and the mandate as one bounded grant |
| Pre-approved changes | ITSM standard changes, such as ServiceNow | Change types allowed without review | The same idea for IT operations. pgmandate applies it to agents' actions |
| Payment mandates | AP2 and Verifiable Intent, contributed by Google and Mastercard to the FIDO Alliance in 2026 | Signed Checkout and Payment mandates for purchases, each open and then closed | The nearest relative, and the source of the word. It covers payments, and the agent carries it as a credential |

## In their own words

Keeping credentials away from agents and asking a person before risky calls is, by late 2026, a common pattern. What others ship, as far as their own documentation says in November 2026:

- **Cloud agent platforms.** [Policy in Amazon Bedrock AgentCore](https://aws.amazon.com/about-aws/whats-new/2026/03/policy-amazon-bedrock-agentcore-generally-available) (generally available since March 2026) applies Cedar policies, conditions on a call's arguments included, at the gateway between agent and tool. DigitalOcean's [Action Gateway](https://docs.digitalocean.com/products/managed-agents/action-gateway/concepts/tool-policies/) (preview) decides allow, ask or deny per tool and keeps the credentials.
- **MCP gateways.** TrueFoundry's and Permit.io's MCP gateways ask a person before a tool call. TrueFoundry's can let one approval cover a set number of minutes; Permit.io's can let a trusted agent skip the approval step. LangSmith's [Tool Gateway](https://docs.langchain.com/langsmith/tool-gateway-policies) (beta, November 2026) blocks a call or asks the caller to approve it. Docker's MCP gateway can require an in-session confirmation through its sandbox policies. Kong's MCP proxy and Enkrypt's gateway apply allow and deny rules and guardrails.
- **Governance libraries.** Microsoft's [Agent Governance Toolkit](https://opensource.microsoft.com/blog/2026/04/02/introducing-the-agent-governance-toolkit/) (MIT, April 2026) runs policies in the agent's process, with approvals, spend limits and a chained audit log.
- **Approval layers of the same kind.** [Preloop](https://github.com/preloop/preloop) (Apache-2.0) includes an MCP firewall with allow, deny, require-approval and require-justification rules, written in YAML with CEL, and takes decisions from a phone, chat or email. SidClaw wraps an MCP server with policy, approval and a hash-chained audit. Countersign ("the model proposes, deterministic code disposes") is a reference implementation with a hash-chained audit and two approvers for high risk. OpenLeash lets owners set policies that agents ask under, and lets agents propose new policies.
- **Credential brokers**, such as Infisical Agent Vault (in preview) and Auth0's Token Vault with asynchronous authorisation, hold the secret and inject it, so the agent never sees it.
- **Identity platforms**, such as Microsoft Entra Agent ID with Agent 365, and Okta, give agents an identity, an owner and access reviews.
- **Agent frameworks** have approval steps inside one run.

What pgmandate does differently, and what it lacks, is in the README's [Why not an API key and an approval step?](../README.md#why-not-an-api-key-and-an-approval-step).
